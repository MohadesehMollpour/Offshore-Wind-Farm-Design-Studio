## Editing and verification

Category folders keep stable IDs, target specifications/prompts, source guides, chart/schema contracts, adapters and tests. The prose guides now distinguish target outputs from working views. Machine-readable `CHARTS.yaml` and some schema/registry labels retain target/scaffold contracts; inspect the runtime dispatcher and result rather than inferring current visualization coverage from those files alone. Rewriting those non-documentation contracts is separate implementation work.

The 54 editable schemas in `config/work_packages.json` are validated and saved under `scenario.inputs.category_inputs`; other native views use their documented inputs/preferences. Drafts do not save automatically. Preserve sibling category inputs when creating a revision. All data/assumptions keep provider/project/site/AOI/reference-point scope, explicit units/time/height and source identity. Follow [the verification guide](VERIFICATION.md) after changes and [the roadmap](ROADMAP.md) for genuine remaining work.

C16/C48/C49/C50 use the new `environment_screening` binding when compatible; otherwise earlier source/register fallbacks remain. [Environmental atlas source methods, limits and continuation](../reports/environmental_atlas.md).
